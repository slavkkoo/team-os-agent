- ЛОГИ И МЕТРИКИ ПРОДА (read-only, вывод уже сжат, персональные данные замаскированы): `connectors/logs-metrics/logs_metrics.py search "<слова или \"фраза\">" [--index <индекс>] [--window 1h|24h|7d]` — поиск логов; `… trace <trace_id>` — все события одного запроса по времени; `… count "<запрос>" --window 24h` — сколько раз; `… prom "<PromQL>"` и `… prom-range "<PromQL>" --window 6h --step 5m` — метрики. Индексы: {{LOGS_INDEXES}}.
  - Используй для ДИАГНОСТИКИ конкретного случая (есть trace_id, id записи, текст ошибки, время). Без идентификатора логи не ищи — попроси его.
  - 0 совпадений в узком окне ≠ «события не было»: расширь окно, прежде чем так утверждать.
  - Диагноз — только из реального вывода, с цитатой (статус, текст ошибки, сервис) и временем. Время в логах обычно UTC — переведи в {{TZ}} и укажи оба.
  - Ошибка HTTP от обёртки = сервис доступен, но запрос или права не те; «недоступен» = сеть/VPN. Передавай как есть, не выдумывай причину.
